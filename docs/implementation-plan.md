# 现货分析 Agent：详细实施方案与任务分工

日期：2026-11-18。项目工作区：`D:\crypto-spot-agent`。研究依据见 [research.md](research.md)。

## 一、产品目标和本轮交付

面向个人现货投资研究，以真实交易所 OHLCV 生成可复核的中文技术分析，结合手工持仓给出条件化策略和风险约束。每条关键结论绑定周期、数据截止时间、指标参数和快照。技术分析与策略收益验证独立验收。

本轮交付可启动的本地 Web MVP：真实公共行情、明确标记的离线演示、多周期技术分析、图表、手工单币持仓评估、策略情景、报告导出，以及可配置的语言模型深度研判入口。完成后保留本地运行入口、必要验证记录和中文阶段提交。

后续独立阶段：正式研究回测引擎、多币组合账本、条件提醒、连续模拟；实盘执行另立需求。本轮没有交易 API，也不读取账户密钥。

## 二、默认配置与可变项

- 市场：无杠杆现货；交易所先支持 OKX、Binance，分别获取各自数据，不静默跨所拼接。报价币先限制 USDT。
- 币种：BTC/USDT、ETH/USDT 起步，后端验证市场确实是现货且可用。
- 周期：1D、4H、1H；最长指标 EMA200，历史长度以稳定性和可用数据确定，默认请求 600 根。
- 界面：本地中文研究台，默认 `127.0.0.1:8765`，公共实时行情与合成演示有醒目标记，显示 UTC/北京时间和最后收盘时点。
- 持仓：当前分析币种数量、可用数量、可选平均成本、可用 USDT、风险预算、单币权重上限、退出参考价。所有比例由用户在界面确认，默认值标为示例配置。
- 模型：基础报告由确定性规则完成；可显式触发 Grok CLI 或 OpenAI-compatible API 的深度研判，失败显示原因，不把基础报告冒充模型输出。应用侧模型无文件、命令或交易工具。

## 三、模块架构

```text
公共行情/演示 → 数据校验与闭合过滤 → TA-Lib + 因果结构识别
                                      ↓
                              多周期状态/策略候选
                                      ↓
手工持仓与风险配置 ──────────────→ 确定性风控
                                      ↓
                            证据快照 → 报告/图表
                                      ↓
                           可选模型研判 → 引用核验
```

依赖方向：`contracts` 为基础；`market` 负责数据；`technicals` 负责计算；`strategy` 消费技术结果；`portfolio` 独立计算风控；`service` 编排并保存快照；`agent` 仅接收精选证据；`api` 提供本地 HTTP；`web` 负责展示。

避免首版微服务、消息队列、向量库、多模型辩论与实时高频栈。行情使用只读公开接口；报告与快照写入项目 data/，运行日志写入 logs/，均不入 Git。

用户明确要求杜绝防御性编程：内部模块直接依约调用；输入格式在入口校验一次，金融业务规则在所属模块实现一次；不编写通用safe函数、不用get链和默认值隐藏契约错误、不捕获所有异常、不静默替换来源、不添加假设性兼容。已知外部服务错误可以转成明确的可见错误，未知程序错误直接暴露在开发日志中以便修复。

## 四、数据与接口契约

### 数据时间语义

1. K 线结构为 UTC 毫秒开盘时间和 OHLCV；周期毫秒映射固定。保留来源、市场类型和抓取时间。
2. 必须满足 `open_time + timeframe <= as_of`，并预留短暂发布宽限；只用已闭合数据生成信号。
3. 拒绝非有限值、负成交量、不合法价格区间、重复时间、乱序；缺口记录并限制依赖连续窗口的分析。
4. 1H 判断只引用当时已收盘的4H/1D。确认摆动点需要右侧两根，首次可用时间在确认后，绝不把后来确认的支撑当成更早已知。
5. 不完整/过期/不足预热数据应返回明确状态并阻止新增仓位建议；演示数据始终保留 synthetic 标签。
6. 原始数据与规则参数生成内容哈希，形成 snapshot_id。运行结果保存模型、代码与规则版本。

### HTTP 接口

| 接口 | 输入 | 输出/行为 |
|---|---|---|
| `GET /api/health` | 无 | 版本、运行状态、模型配置状态，无凭据 |
| `POST /api/analyze` | source、exchange、symbol、可选持仓与风险 | 完整快照、周期分析、图表数据、策略情景、风控和基础报告 |
| `POST /api/import` | 有界 CSV 文本、周期、交易所/交易对标签 | 校验后只分析导入周期，不伪造缺失周期；历史数据标记导入回放 |
| `GET /api/reports/{id}` | 严格格式ID | 已归档结果；不能传任意路径 |
| `GET /api/reports/{id}/markdown` | 同上 | UTF-8 Markdown 下载 |
| `POST /api/reports/{id}/insight` | 问题与已保存ID | 经结构校验的模型研判，包含证据ID和明确的模型状态 |

错误统一 `error.code/message`；限制请求大小、币种、周期、历史根数、问题长度、外部调用超时。部署仅绑定 loopback，限制 Host/Origin，网页没有第三方 CDN 依赖。

### 报告关键字段

`snapshot_id / source / exchange / symbol / market_type / as_of / fetched_at / version / quality / timeframes / consensus / scenarios / portfolio / evidence / report`。

每条 evidence 有唯一 ID、周期、已收盘时间、类别、已计算值、参数、解释与限制。输出“证据强弱”而非虚构概率。模型输出采用有限 JSON 字段和证据 ID 列表；严格校验 ID，基础事实和价格仍从快照渲染。

## 五、技术分析规范

| 类别 | 算法和默认参数 | 解读边界 |
|---|---|---|
| 趋势 | EMA20/50/200及斜率，ADX14/+DI/-DI | ADX只表示强度，不能独自确定方向；相关均线指标不重复计分 |
| 动量 | RSI14，MACD12/26/9 | 超买不等于必须卖，超卖不等于立即买；结合趋势、结构解释 |
| 波动 | ATR14、ATR/收盘价，BBANDS20/2/2 | 波动扩张/收缩和止损噪声范围；布林位置不单独构成交易信号 |
| 量价 | 相对前20根成交量、OBV | 本根量比基准不含本根；只描述成交量，不声称主力资金流 |
| 结构 | 2+2确认摆动点、HH/HL/LH/LL，ATR容差价区 | 保留发生与确认时间；支阻基于已确认点，不保证价格反转 |
| 形态 | TA-Lib吞没、锤头、十字及实体/影线 | 写明位置和确认不足；形态是描述证据，不自动加仓 |
| 多周期 | 日线方向、4H结构、1H观察触发 | 周期冲突明确披露；高周期缺失不强行得出共振 |

每周期报告至少覆盖上述七类，显示最新数值及参数，并给出支持证据、反证、观察条件。价格结构识别和指标数组均只依赖当时或过去数据。

## 六、策略与持仓规范

市场状态：上升、下降、震荡/低趋势、冲突、不足数据。首批候选：趋势回踩、突破后回踩、区间均值回归。情景包含确认条件、失效条件、参考价区、估计风险收益和不适用原因，不默认已经触发交易。

现货只允许持有现金、持币和卖出已有数量。下跌状态可以等待或降低敞口。禁止自动借币、杠杆或负持仓。

持仓权益 = 可用现金 + 当前币种市值；如没有其他资产，不冒充全账户净值。成本未知就不计算收益/回本价。可用数量不得大于总数量。

新增多头数量同时受三项限制：

`min(剩余风险预算 / 含双边成本的每币估计风险, 含买入费的现金可买量, 单币权重余量可买量)`。

已有持仓风险先扣除；退出参考价必须低于当前计划入场价，费用/滑点非负。无法有效估计风险、价格失效、数据过期、周期冲突时，新增数量为0并说明原因。计划数量为分析参考，未读取交易所精度/最小额时不声称可直接下单。

## 七、模型研判与安全

编码阶段 Grok 是开发协作者；运行时 Agent 的模型是可选功能，两者配置和权限分开。

Grok CLI 编码使用项目目录与任务文件：`grok --model grok-4.7 --reasoning-effort high --prompt-file tasks/<任务>.md ...`。先核实实际认证；不读取或打印凭据，不把无权限错误当成成功。

应用模型只接收精简的数值/条件证据和用户问题，不接收本机路径、密钥、原始日志。只允许结构化研判、引用与反证，不授予网络、命令、文件或交易工具。提供进程/HTTP超时、并发限制和明确错误状态。任何模型输出在页面中按文本展示，不直接作为HTML或命令。

深度研判的结论不能改写程序计算的仓位或关键价格。引用不合法就拒绝结果。未校准的文字判断须标注“模型解释”，不伪装成确定性事实或概率。

| G2 | 确定性报告Markdown导出 | Grok 4.7 high | 只消费既定字段，不生成策略/数值；主 Codex 审计 |
| P1 | 公共行情、闭合/缺口规则、演示、数据快照 | 主 Codex | 必要数据边界测试、一次真实接口核验，中文提交 |
| P2 | 指标、因果结构、多周期、策略候选 | 主 Codex | 指标对照和前缀不变性验证，中文提交 |
| P3 | 单币持仓风险、报告证据与编排 | 主 Codex | 现金/风险/现货边界验证，中文提交 |
| P4 | API、本地研究台、图表与交互 | 主 Codex | 本地端到端必要检查与实际浏览器查看，中文提交 |
